# LeadDesk

A small lead-capture tool: a public landing page with a lead form, and an
admin dashboard to manage submissions.

**Live app:** https://leaddesk-neon.vercel.app/
**Admin:** https://leaddesk-neon.vercel.app/admin (test credentials below)

## Stack

- Next.js 15 (App Router, JavaScript)
- Tailwind CSS
- `motion` (for scroll-reveal animations on the landing page)
- Supabase (Postgres database + Auth)
- Deployed on Vercel

## Data model

One table, `leads`:

| column       | type      | notes                                      |
|--------------|-----------|---------------------------------------------|
| id           | uuid      | primary key, auto-generated                |
| name         | text      | required                                   |
| email        | text      | required, validated format                |
| budget_range | text      | required, one of a fixed set of ranges     |
| message      | text      | required, 10–2000 chars                    |
| status       | text      | `New` / `Contacted` / `Closed`, default `New` |
| created_at   | timestamptz | auto-set on insert                        |

Schema + Row Level Security policies live in `supabase.sql` — run that once
in the Supabase SQL editor when setting up a new project.

## Auth approach

Admin auth uses **Supabase Auth** (email + password), not a hardcoded
string:

- Admin accounts are created in the Supabase dashboard (Authentication →
  Users), not signed up from the app — there's no public sign-up form.
- Sessions are handled via `@supabase/ssr`, which stores the session in
  httpOnly cookies and refreshes it automatically.
- `middleware.js` runs on every request to `/admin/*`, checks for a valid
  session, and redirects to `/admin/login` if there isn't one.
- The database itself enforces the boundary too, via Postgres Row Level
  Security: the `anon` role can only `insert` into `leads` (for the public
  form), while `select` and `update` require the `authenticated` role. So
  even if someone bypassed the frontend, they couldn't read or edit leads
  without a real session.

## Validation

Lead form fields are validated in two places using the same rules
(`lib/validateLead.js`):

- **Client-side**, before submitting, so users get instant feedback.
- **Server-side**, in `app/api/leads/route.js`, so the API can't be
  bypassed by skipping the UI (e.g. a raw `fetch`/`curl` request with bad
  data gets rejected with field-level errors).

## Local setup

1. Clone the repo and install dependencies:
   ```
   npm install
   ```
2. Create a free project at [supabase.com](https://supabase.com).
3. In the Supabase SQL editor, run everything in `supabase.sql`.
4. In Supabase → Authentication → Users, add an admin user (email +
   password, check "Auto Confirm User").
5. Copy `.env.local.example` to `.env.local` and fill in your project URL
   and anon key (Supabase → Project Settings → API).
6. Run the app:
   ```
   npm run dev
   ```
